HYX SCENE STUDIO / 使用说明 / V2

从运动编排，到固定轨迹的环境对照。

编辑器通过 CARLA Python API 操作你已经启动的地图。左侧选择参与者与行为预设，中间布置车辆与路线，右侧编辑属性，底部按秒编排多车动作。

启动运动编排环境对照手动接管文件与记录边界与排错返回编辑器 ↗

1. 启动

  1. 启动 CARLA / UE 编辑器，打开 map10，点击 Play。API 默认地址为 127.0.0.1:2000。
  2. 在项目根目录运行 Start-SceneStudio.cmd，保持服务窗口打开。也可执行：
    python -m pip install -r requirements-studio.txt
python -m scene_studio.server
  3. 浏览器访问 http://127.0.0.1:8877/。标题栏应显示当前地图名称。
  4. 首次使用可选“时间轴示例 · 加速与变道”或保留的 Scene1_01 等条件事件模板。服务器会从随代码附带的模板初始化缺失场景，不覆盖已有场景。

建议 Python 3.10、CARLA 0.9.15。编辑器不会自动切换地图。当前项目的 map10 为自定义地图，地图资产不包含在代码仓库中。运行时由本编辑器统一推进固定步长仿真，请停止其他正在调用 world.tick 的客户端。

2. 运动编排：路线、速度与多车行为

01 布置选择车型、位置与主车，绘制道路路线。
02 编排应用行为预设，在时间轴上调整动作与目标速度。
03 录制实机运行，保存实际位置、姿态、速度与输入控制。
  1. 选择顶部“运动编排”。左侧点选车辆，使用中间的移动/旋转控件；“车道吸附”会将初始位置放到最近道路上。按 F 聚焦。
  2. 右侧设置初始速度、加减速度和初态。“启动即具有目标速度”是初始赋速，之后通过物理油门与刹车控制。未勾选则从静止开始。
  3. 点“路线”，依次在道路上点击路线点；右侧可修改点坐标或删除。车辆沿地图道路网络连接这些点。空路线会根据当前车道向前延伸。
  4. 从左侧应用匀速、起停、前车急刹、切入、超车、跟车或静止预设。主车与背景车都可使用。预设替换当前车辆的片段，并将其旧条件事件中的运动动作替换为标记，保留其他参与者的事件依赖；原始模板可重新加载。
  5. 底部点击“＋速度”等添加片段。拖动片段改变开始时刻，拖动右边缘改变持续时间。点击片段在右侧填写目标速度、方向、车距等。吸附精度可切换 0.1 / 0.5 / 1 秒。
  6. 点击“预演”观看编辑器估计的运动。点击时间刻度可查看任意时刻；“实机预览”则在 CARLA 中按预演位置布置并显示真实相机，可拖动时间查看。
  7. 点击“运行并录制”开始物理运行。运行中编排被冻结，可暂停、手动接管、调整环境或停止。结束后在“轨迹录制库”查看实际录制。
片段含义
速度从之前目标速度过渡到新目标，支持线性或平滑插值；结束后保持新目标。实际车辆仍受加减速与物理约束。
变道在指定时长内平滑改变横向目标偏移，结束后保持新偏移。多个变道累加；需要在道路上选择存在且同向的目标车道。
跟车指定前车、反应延迟、最小净车距和时间车距。该车目标速度同时作为速度上限；只在目标位于前方同车道时采用跟车约束。
制动片段内施加 0–1 制动强度，期间油门为零；结束后恢复自动速度控制。速度和制动片段不允许时间重叠。
灯光在片段内设置灯光位状态。结束后保持最后灯光状态；需要关闭时添加关闭灯光片段。

“预演”是路径与目标速度估计，不是物理仿真。跟车的真实速度、碰撞、条件事件和人工输入只能通过实机录制核验。时间轴中的车道偏移不是路权或避碰保证；编辑后应检查道路和风险时序。

3. 环境对照：保持实际车辆轨迹

  1. 在运动编排模式完成一次录制。
  2. 点击“固定轨迹 · 环境”或“轨迹录制库”，选中基准。编辑器载入基准的车辆与时间轴并锁定。
  3. 右侧“环境”选择清晰日光、低角度日光、雨天或暮色等预设。可细调太阳角度、云量、雾、雨量、湿润、曝光、Gamma、Bloom 和运动模糊。
  4. 点击“重放并录制”。环境模式关闭录制车辆物理，逐帧提交记录的位置与姿态，显示的速度取自原录制。服务端会校验基准的运动字段，拒绝夹带位置、路线、速度或时间轴变化。
  5. 预览或运行中也可点“应用到实机预览”即时更新天气与相机；完整 A/B 对照建议先停止，选定参数后从头重放。
  6. 到运行文件夹比较相同时间的 shot_0002000.jpg 等截图。时间单位为毫秒，示例是第 2 秒。日志记录应用环境的时刻。

这是记录位置的确定性重放，适合把车辆运动固定后比较视觉环境。它不是在不同天气下重新计算轮胎、摩擦与碰撞的物理仿真；湿润参数也不会自动修改轮胎摩擦。相机可能因渲染负载丢帧，比较截图须使用确实存在的相同时间点。

要修改车辆行为，点“运动编排”生成一个可编辑副本，修改后重新录制。录制 JSON 与场景 JSON 必须一起保留，单独导出环境场景不包含基准轨迹数据。

4. 主车随时接管

在物理运行或固定轨迹重放期间，点击“M 接管”或按 M。驾驶画面会放大，HUD 显示当前控制权。接管优先级高于所有时间轴动作；只有“R 自动”会主动交还控制权。

输入作用
M请求手动接管；默认键盘，也可使用已选择的手柄/方向盘。
W / S油门 / 制动。
A / D向左 / 向右转向。
Space手动时全制动；停止运行时播放/暂停编辑器预演。
R恢复物理自动跟随路线，不跳回原录制位置。
Ctrl+S / Ctrl+Z / Ctrl+Y保存 / 撤销 / 重做编排。

浏览器必须保持焦点。切换窗口、断开设备或超过约 0.35 秒未收到有效输入时，车辆进入制动；控制权仍保持手动。重新点击接管恢复输入。服务器使用控制权代数与序号拒绝旧输入包。

环境重放中接管会恢复主车物理，立即标记为“主车轨迹已偏离基准”。背景车继续按基准重放。恢复自动也不会抹掉该标记或把主车传送回原位置，因此这次记录不能再宣称主车轨迹完全一致。

手柄与方向盘

点击“输入 ⚙”，连接设备并按一次按钮，观察设备列表。设置设备序号、转向轴、中心、半量程与死区；踏板可选择按钮或轴。轴踏板要分别填写完全松开与踩到底的原始值，可支持正向或反向轴。保存后重新接管。先在低速空场景确认方向与踏板响应。

当前开发机器未连接手柄/方向盘，实机接管测试使用键盘与 API 输入。浏览器 Gamepad API 兼容性取决于设备与浏览器；不包含 Logitech 力反馈 SDK 集成。布置预览不进行手动驾驶，请启动运行。

5. 保存、导出与运行记录

路径内容
studio_data/scenes/*.json保存的场景。再次保存前会备份旧版本到 history。
studio_data/runs/<运行编号>/scene.json启动时的场景配置。
take.json + trajectory.jsonl录制元数据、基准配置与每一仿真帧的实际状态。两个文件共同组成可重放轨迹。
telemetry.csv时间、世界帧号、控制权、实际姿态、速度、油门、制动与转向。环境模式速度来源标记为 recorded。
events.json / console.txt事件触发、接管、碰撞、失败与清理记录。
shot_*.jpg按整数场景秒保存的实机相机截图。

顶部“文件”菜单可导入/导出场景 JSON。另存为会创建新场景。运行数据、被试数据、缓存和本地历史不应上传代码仓库。分享环境对照时，需另外传递相应运行目录并保持其编号一致。

6. 运行边界与排错

  • 连接失败：确认 CARLA 已 Play、API 端口 2000 可访问；点击刷新连接。
  • 位置被占用：检查两辆车是否重叠、是否放在路面内。停止后调整位置或使用车道吸附。
  • 路线不连通：将路线点放在连通道路上，避免跨越隔离带或地图断点。
  • 片段超出时长或重叠：右侧填写合法时间，先延长场景再添加后续片段。同一动作通道及速度/制动重叠会被拒绝。
  • 天空/湿地面与预期不同：map10 的导入材质与天空蓝图对 CARLA 天气参数支持有限。雨量与湿润数值成功应用不意味着每块材质都会出现积水反射；此代码未重建 UE 材质资产。
  • 帧率：编辑器默认固定步长 0.05 秒、20 Hz 仿真。慢机可能比墙钟慢，HUD 相机 FPS 是到达率，不等于前述四相机性能测试结果。
  • 停止与清理：停止按钮等待工作进程销毁自身创建的参与者与相机，再恢复原世界步长和天气。不要强杀 UE 或运行进程。若发生硬崩溃，请检查 CARLA 世界设置后再启动。
  • 实验使用：原 Scene 模板的条件事件仍保留，但新物理控制器并不保证与旧脚本的运动完全相同。正式实验需核验风险显现时刻、间距、碰撞与接管时序。
